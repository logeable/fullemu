# 第 52 阶段：块设备对象与扇区读写接口

## 目标关联

文件系统需要通过稳定接口读写存储，而不能直接操作 VirtIO 寄存器或 virtqueue。本阶段在具体驱动和未来文件系统消费者之间建立最小块设备接口，为文件系统读取元数据和更新数据提供基础。

## 学习重点

- 上层按逻辑扇区读写，不需要了解 VirtIO MMIO 寄存器和描述符格式。
- 具体设备对象持有设备容量、MMIO 基址和请求序号；一次可变借用覆盖完整请求，因此当前串行请求不需要额外锁。
- 设备 DMA 缓冲区的物理地址和内核访问它们的虚拟地址是不同概念，启动层负责将静态 DMA 区域换算为设备使用的物理地址。

## 实现范围

- 新增 `block::BlockDevice` 契约，提供扇区数量、单扇区读取和单扇区写入；当前逻辑扇区大小固定为 512 字节。
- `driver::virtio::block::VirtioBlockDevice` 探测并初始化现代 VirtIO MMIO 块设备，并实现该读写契约。
- `driver::virtio::virtqueue` 管理通用 split virtqueue 描述符、环形区和完成轮询；块驱动负责配置队列寄存器并通知设备，同时提供块请求头、数据与状态缓冲区。
- 写请求使用 VirtIO 块设备写操作类型；描述符标明数据由设备读取、状态由设备写回。
- 读写请求复用单个静态 split virtqueue；队列模块维护 available/used 序号，使一个设备对象可以连续提交多个串行请求。
- 启动层通过 `BlockDevice` 接口读取扇区 0 的镜像签名，再向专用测试扇区 1 写入完整扇区并逐字节读回比较。

## 暂不实现

- 多块设备对象、队列动态分配、并发或异步请求、设备中断和运行时设备注册。
- 多扇区传输、写缓存刷新、flush/barrier、错误恢复或设备移除。
- 文件系统、分区解析、用户态文件 I/O 和从磁盘装载 ELF。
- 磁盘持久化保证：本实验只检查写请求完成后能读回相同内容，不执行 flush，也不验证断电后的持久性。

## 模块边界

`block` 定义与设备类型无关的 512 字节扇区读写契约；`driver::virtio::mmio` 处理现代 VirtIO MMIO transport 探测、寄存器范围校验和通用设备寄存器；`driver::virtio::virtqueue` 管理 split virtqueue 描述符链、环形区和完成轮询；`driver::virtio::block` 处理块设备配置、块请求格式、队列寄存器编排和扇区读写；`startup` 解析 FDT 候选范围、提供 DMA 物理地址并通过通用接口执行读写自检。块设备契约不依赖 FDT、VirtIO 或文件系统。

当前 DMA 队列和请求缓冲区仍是驱动模块中的静态资源，因此同一时刻只允许一个 `VirtioBlockDevice` 活动。对象正常销毁时复位设备并释放队列占用；若请求超时或队列状态损坏，则保留占用，避免设备仍在 DMA 时复用缓冲区。设备对象的 `&mut self` 接口保证其请求串行；尚不能安全支持多个并发设备对象或运行时多进程并发访问。

## 验收方式

```sh
make build
make run
```

`make run` 每次默认创建并在 QEMU 退出后删除一个临时双扇区测试镜像：扇区 0 用于读取检查，扇区 1 是写测试区。启动日志应先显示扇区 0 签名，再显示扇区 1 写后读回成功；内核还会确认扇区 0 未被写测试改变。若设置 `BLOCK_IMAGE`，目标路径必须不存在，脚本会创建并保留该新镜像；已有路径会被拒绝。该检查验证 VirtIO 写请求和紧随其后的读回，不代表数据已通过 flush 持久化。

## 后续连接

文件系统可以依赖 `BlockDevice` 读取超级块、目录和文件内容。届时再按文件系统实际需要增加多扇区请求、运行时设备持有与同步，以及进程页表中设备寄存器访问或内核统一 I/O 路径。
