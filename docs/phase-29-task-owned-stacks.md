# 第 29 阶段：任务拥有独立栈

## 目标关联

进入动态任务创建前，任务不能再依赖按固定索引切分的全局栈数组。本阶段让每个 `Task` 拥有自己的内核陷入栈和用户栈 backing，并让 Sv39 为两种栈建立符合特权边界的映射。这为之后按需创建地址空间和任务解除固定栈数组的阻塞。

## 实验问题

**任务记录可能移动或退出时，如何保证栈地址在任务运行期间稳定，并确保用户栈只在所属地址空间中以 U-mode 权限可见？**

## 实现范围

- 删除全局固定的用户栈和内核陷入栈数组。两种栈各自拥有 4 个 4 KiB 页帧；页帧与任务表中的 `Task` 分开分配，因此任务表扩容不会移动栈 backing。
- 内核栈使用连续页帧的恒等地址。页帧池位于内核 BSS，所有任务页表都将该区域映射为 S-mode 可访问、U-mode 不可访问；陷入入口通过当前任务的 `sscratch` 切换到其内核栈。
- 用户栈使用独立页帧，所有任务使用相同 Sv39 用户虚拟范围 `0x0000003fffffb000..0x0000003ffffff000`，但每个地址空间映射到不同物理页，权限为 `URW-`。该区域处于 Sv39 低半部规范地址范围，并与程序镜像区分离。
- 系统调用缓冲区检查改为查询任务拥有的用户栈范围。
- 任务退出时先切换到另一地址空间并销毁旧页表，再释放旧用户栈页帧。内核调度器此时仍运行在退出任务自己的内核栈上，因此内核栈记入待回收项，在下一次进入其他任务的陷入栈后释放。
- 任务上限仍为 8，程序镜像仍在固定槽位；本阶段不实现运行时任务创建、索引复用或用户栈增长。

## 资源与映射不变量

- 栈页帧由任务资源记录持有；帧分配失败时不会返回部分用户栈分配。
- 每个内核栈要求物理页连续，以便恒等映射下形成连续的 RISC-V 栈地址；每个用户栈允许物理页不连续，由页表逐页映射。
- 内核栈页帧位于所有地址空间共同映射的内核区域，且 PTE 不设置 `PTE_USER`。用户栈只在所属任务页表中以 `PTE_USER | PTE_READ | PTE_WRITE` 映射；其物理页在共同内核恒等映射中的别名仍为 S-only。
- 已退出任务的用户栈在旧地址空间销毁前不会归还；活动内核栈永远不会由正在使用它的调度路径释放。

## 运行与验收

```sh
make fmt-check
make build
make run BOOT_MODE=batch LOG_LEVEL=debug
make run BOOT_MODE=shell LOG_LEVEL=info
```

批处理模式应显示每个任务独立的栈物理 backing、共同的用户栈虚拟范围，以及页表中用户栈的 `URW-` 映射；内核栈地址落在共同的 `SRWX` 内核映射中。任务应继续完成定时器切换、系统调用、退出及异常隔离。shell 模式应仍能通过 `read` 和 `write` 系统调用交互。

## 后续连接

任务现在拥有稳定的栈资源，但地址空间仍由启动时一次性按任务索引批量建立，任务上限也受批处理程序数量限制。下一步若实现运行时创建任务，应把单个地址空间的创建接口、稳定任务 ID 和资源准备失败时的回滚连接起来；回收内核栈仍需遵守延迟释放约束。
