# 第 28 阶段：FDT 驱动的物理页帧与堆后备区

## 目标关联

任务栈、页表和内核对象都需要运行期内存。此前堆和页帧池各自在 BSS 中占固定区域，无法按机器实际 RAM 扩展。本阶段把已经解析的 FDT RAM 范围接入物理页帧分配器，并让堆从它取得后备页，为动态任务和更完整的地址空间管理建立单向资源依赖。

## 实验问题

**内核怎样把固件描述的 RAM 转成可安全分配的页帧，同时避免堆和页帧分配器互相依赖？**

```text
FDT 中的内存信息
    └─ 页帧分配器：按页追踪可用物理区间，不使用堆
         ├─ 页表和任务栈取得页帧
         └─ 堆取得连续页帧，再将它们切分成 Rust 对象
```

## 实现范围

- 启动先解析并拥有无堆 `FdtMemoryInfo`，然后初始化页帧分配器，最后初始化堆。页帧分配器的元数据保存在固定容量 BSS 区间表中，因此初始化它不需要调用全局分配器。
- 页帧分配器只考虑 `FdtMemoryInfo::memory_regions()` 描述的 RAM，并逐页使用 `contains_unreserved_ram_region` 排除固件 reserve map 与 DTB 自身占用范围。
- 可分配起点不早于链接器的 `__bss_end`，因此内核映像、启动栈和分配器元数据不会被回收；链接器预留的用户程序镜像槽也不会进入页帧池。
- 通过已排序的可用区间表执行 first-fit 单页或连续页分配。释放时按地址插入空闲区间并与相邻区间合并。区间元数据容量为 256，FDT RAM 区域容量为 32；超出容量会明确报错。
- `PhysicalFrame` 表示单页所有权；`PhysicalFrameRun` 表示连续页范围。低层页帧模块只提供这两种所有权接口，不构造 `Vec`，从而不依赖堆。
- 内核堆在启动期从页帧分配器取得 64 个连续页（256 KiB），并永久持有这段后备区。堆分配器仍只管理字节和对象，不负责释放或追踪单页。
- 每个 Sv39 地址空间将 FDT 描述的 RAM 建立为 S-mode 恒等映射，使动态分配的页表、堆和内核栈在切换页表后仍可访问。内核映像现有映射随后覆盖为当前内核权限；用户程序仍通过其 U-mode 虚拟映射访问。

## 暂不实现

- FDT 的 `/reserved-memory` 子树尚未解析；当前只遵守 `FdtMemoryInfo` 已提取的 RAM、reserve map 和 DTB 范围。
- 物理页范围元数据有固定上限；尚未把区间描述符本身放入受管理内存，也未实现伙伴系统或更复杂的连续页搜索策略。
- 堆容量仍固定为 256 KiB，尚未按需扩展或归还空闲页帧。
- 可分配页起点保守地放在 `__bss_end` 之后，用户程序加载槽被排除；尚未根据完整固件内存图回收低端 RAM 或其他平台专用区域。
- Sv39 为每个任务将 FDT RAM 按 4 KiB 页面恒等映射；尚未采用大页、直接映射偏移或按需映射。

## 依赖与不变量

- `device_tree::memory_info` 不依赖分配器；它在堆启动前拥有固定容量的 FDT 摘要。
- `frame_allocator` 依赖 `FdtMemoryInfo` 和静态区间元数据，不依赖 `heap`、任务或页表。
- `heap` 依赖页帧分配器取得连续物理后备页；当前 QEMU `virt` 启动保持恒等寻址，因此堆初始化时可以直接使用该物理地址，Sv39 激活后 RAM 恒等映射继续提供同一虚拟地址。
- 页帧可分配性来自 FDT RAM 范围与已知启动占用范围的交集计算。任一候选页必须完整处于单个 RAM 区域，且不能与 DTB 或固件保留范围重叠。

## 验证

```sh
make fmt-check
make build
make run
```

启动应先输出 FDT RAM 与 DTB 范围，再成功初始化页帧分配器和 256 KiB 堆；页帧自检应分配、脏写、释放、清零复用并恢复空闲页数。启动 shell 或批处理任务时，Sv39 页表、内核栈和用户栈均应继续正常工作。
