# 第 25 阶段：固定物理页帧池

## 目标关联

内核堆已能按字节为 `Vec` 等对象分配内存，但 Sv39 页表、用户栈和用户地址空间需要以页为单位管理物理内存。本阶段先建立固定物理页池和页帧所有权接口，再将 Sv39 根页表与中间页表页改为按需分配；用户栈和程序镜像仍由静态区域提供。

## 实验问题

**内核怎样追踪固定物理页池中哪些 4 KiB 页正在使用，哪些可以再次分配？**

## 实现范围

- 在内核 BSS 中保留 128 个连续、4 KiB 对齐的页帧，共 512 KiB。链接布局仍须保证内核末尾早于用户程序加载区 `0x80400000`。
- 新增 `kernel::frame_allocator`，用位图记录每个页帧的占用状态；分配时从低地址开始寻找空闲帧，释放时验证地址属于页池、按页对齐且当前处于已分配状态。
- 提供 `allocate_frame()` 和 `allocate_zeroed_frame()` 两种明确接口：普通分配返回未初始化页；清零分配会在交付所有权前将整页写零，供页表等必须从空状态开始的结构使用。
- `PhysicalFrame` 表示当前页池中的一个页帧，并作为不可复制的所有权令牌；释放操作消费该令牌。分配器按单 hart S-mode 中断守卫保护位图更新。
- 启动时显式初始化页帧分配器，再由统一的启动自检入口检查：分配三个不同页帧、将其中一页写入非零值、释放后用清零接口重新取得并逐字节检查，最后确认全部 128 页都已归还。
- `kernel::memory` 为每个地址空间从页帧池申请独立根页表；映射需要新建中间层时，再按需申请并清零页表页。PTE 中保存物理地址，根页表地址由地址空间索引表记录。
- 页表构造、激活和调试遍历都会确认根页表或子页表仍对应页池内已分配的页帧；页帧令牌通过 `into_address()` 转交给由页表树持有的页表页。

## 暂不实现

- `allocate_frame()` 不会清零内容；消费者必须先初始化再读取。页表接入时应使用 `allocate_zeroed_frame()`。
- 页帧池固定预留在内核 BSS，不扫描 FDT，也不回收 OpenSBI、设备或其他固件保留内存。
- 用户栈和用户程序镜像仍由现有静态布局提供；本阶段不做动态用户内存映射。
- 页表初始化失败仍按启动致命错误处理，不尝试回收部分构造的页表。
- 页帧分配器不接入 `GlobalAlloc`。它管理整页物理内存，`kernel::heap` 继续管理对象字节。
- 中断守卫只适用于当前单 hart 配置，不提供多 hart 同步。

## 运行与验收

```sh
make fmt-check
make build
make run
```

QEMU 启动日志应报告页池起始地址、页数和页大小，并确认分配地址对齐且互不相同，脏页经清零分配后全页归零，释放后的页可被复用，最后空闲页数恢复为 128。启用页表调试日志时，各任务应显示不同的根页表物理地址；批处理模式下可检查多个地址空间均成功建立。内核 BSS 和整体映像范围应仍处于 `0x80400000` 用户程序加载区之前。
