# 第 25 阶段：固定物理页帧池

## 目标关联

内核堆已能按字节为 `Vec` 等对象分配内存，但 Sv39 页表、用户栈和用户地址空间需要以页为单位管理物理内存。当前页表页和用户栈仍由静态数组提供；本阶段先建立可分配、可回收的物理页帧接口，为后续替换静态页表池做准备。

## 实验问题

**内核怎样追踪固定物理页池中哪些 4 KiB 页正在使用，哪些可以再次分配？**

## 实现范围

- 在内核 BSS 中保留 128 个连续、4 KiB 对齐的页帧，共 512 KiB。链接布局仍须保证内核末尾早于用户程序加载区 `0x80400000`。
- 新增 `kernel::frame_allocator`，用位图记录每个页帧的占用状态；分配时从低地址开始寻找空闲帧，释放时验证地址属于页池、按页对齐且当前处于已分配状态。
- `PhysicalFrame` 表示当前页池中的一个页帧，并作为不可复制的所有权令牌；释放操作消费该令牌。分配器按单 hart S-mode 中断守卫保护位图更新。
- 启动时显式初始化页帧分配器，再独立运行实验：分配三个不同页帧、检查对齐、释放并验证复用，最后确认全部 128 页都已归还。

## 暂不实现

- 页帧内容分配时不自动清零；将来把帧用作页表或映射给用户前，消费者必须明确初始化内容。
- 本阶段的页帧池固定预留在内核 BSS，不扫描 FDT，也不回收 OpenSBI、设备或其他固件保留内存。
- 现有静态页表池、用户栈和用户程序镜像布局保持不变；本阶段的启动演示尚未替换它们。
- 页帧分配器不接入 `GlobalAlloc`。它管理整页物理内存，`kernel::heap` 继续管理对象字节。
- 中断守卫只适用于当前单 hart 配置，不提供多 hart 同步。

## 运行与验收

```sh
make fmt-check
make build
make run
```

QEMU 启动日志应报告页池起始地址、页数和页大小，并确认分配地址对齐且互不相同，释放后的页可被复用，最后空闲页数恢复为 128。内核 BSS 和整体映像范围应仍处于 `0x80400000` 用户程序加载区之前。
