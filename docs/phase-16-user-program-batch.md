# 第 16 阶段：多个嵌入式用户程序批量执行

## 目标关联

单个用户程序已能调用 `write` 输出并用 `exit` 结束，但内核还不能按顺序运行多个独立应用。批量运行使现有加载器和退出系统调用组成最小应用执行流程，是后续 shell 启动外部命令、观察程序生命周期的直接基础。

## 实验问题

**没有文件系统和进程调度器时，内核如何运行一组独立构建的程序？** 本阶段采用早期批处理系统的思路：把应用镜像预先嵌入内核，按固定清单逐个装入同一个加载区；当前程序调用 `exit` 后，内核复用陷入现场启动下一个程序。

## 实现范围

- `user/src/bin/` 集中放置每个独立用户程序的入口源码；Cargo 自动按文件名发现二进制目标。`user/src/lib.rs` 和 `user/src/syscall.rs` 提供共享运行时，避免每个程序重复定义 panic handler 和引入启动汇编。`make build-user` 构建这些二进制，用 `rust-objcopy` 转成原始镜像，并自动生成 `user/target/<目标三元组>/release/user-programs.manifest`；新增或移除入口源码会同步改变清单内容。
- 内核包的 `build.rs` 将清单中的镜像复制到 Cargo `OUT_DIR` 并生成静态程序清单。未设置 `FULLEMU_USER_IMAGE_MANIFEST` 时生成空清单，因此 `cargo build` 可独立构建内核；`make build` 先执行 `build-user`，再设置环境变量完成包含用户程序的完整构建。`make build-kernel` 显式清空该变量，构建不嵌入用户程序的内核。
- 加载器按清单索引返回程序名称、入口和镜像长度，将镜像复制到同一个固定 64 KiB 区域。每次装入前清零整个区域并执行 `fence.i`。
- 用户程序共享一个静态栈；每次启动前由内核清零。批次仅串行执行一个用户程序，不保存并发任务的上下文。
- 用户程序调用现有 Linux RISC-V `exit` syscall 后，陷入处理器在原内核陷入栈上构造下一个程序的用户陷入帧并恢复执行。清单耗尽后记录批次总数并让 hart 等待。
- 第一个程序通过 fd 1 输出问候，并检查 `write` 返回的字节数；第二个通过 fd 2 输出诊断文本并检查返回值；第三个向无效 fd 3 写入，识别 `-EBADF` 后再次输出，证明系统调用错误会返回用户态且程序可以继续执行。三个程序均根据行为是否符合预期以状态码 0 或非零值退出。

## 暂不实现

- 镜像仍是原始二进制，没有 ELF 段解析、磁盘/文件系统读取、动态应用发现或命令行参数。
- 不带用户镜像清单构建出的内核只会启动并进入等待状态，不会运行批处理程序；当前 QEMU 完整实验仍应使用 `make build` 或 `make run`。
- 程序复用固定物理加载区和用户栈，`satp=BARE` 仍允许 U-mode 访问内核 RAM；这不是地址空间隔离，也不适合运行互不信任的程序。
- 没有同时驻留的任务、抢占调度、独立堆、父子关系、`wait` 或退出资源回收。
- fd 1 与 fd 2 当前都输出到同一个 UART，因此标准输出和标准错误尚无设备级区分；本阶段只验证文件描述符参数和系统调用返回行为。
- 一个程序陷入非系统调用异常时，当前批次停止；本阶段只用 `exit` 作为正常批次控制路径。

## 运行与验收

```sh
make fmt-check
make build
make run
```

QEMU 串口应依次显示 `[stdout]` 问候、`[stderr]` 诊断文本，以及识别 `EBADF` 后继续运行的确认文本；内核应报告三个程序均以状态码 `0` 结束，最后报告“用户程序批次完成，共运行 3 个程序”。用户输出不带内核日志前缀。

## 后续连接

顺序批处理证明内核可依次管理多个应用，但没有同时驻留的执行现场。第 17 阶段开始让多个 U-mode 程序同时驻留并协作切换；它们仍共享可访问的内存，之后需要 Sv39 建立真正的地址空间隔离，才能安全运行互不信任的程序。
