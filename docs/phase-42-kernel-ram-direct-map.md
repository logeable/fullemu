# 第 42 阶段：以内核高半区直接映射访问 RAM

## 目标关联

第 41 阶段让 Rust 内核主体、全局数据和运行栈迁移到高半区，但页帧、堆和页表仍通过 RAM 低地址恒等映射访问。这样物理地址和 Rust 指针仍容易混淆，也使每张任务页表必须继续保留整个 RAM 的低地址别名。

本阶段建立明确的 RAM 访问约定：页帧和页表记录物理地址；Rust 解引用 RAM 时使用高半区直接映射虚拟地址。用户程序可见的虚拟映射仍由任务地址空间单独建立。

## 学习重点

- **物理地址不是 Rust 指针。** 将物理地址整数强转为指针后，CPU 会把它解释成当前页表中的虚拟地址；旧代码只有依赖恒等映射才成立。
- **直接映射提供稳定换算。** 本项目使用 `内核虚拟地址 = 0xffffffc000000000 + 物理地址`；物理地址仍写入 PTE 和 `satp`，指针则经 `kernel::memory::address` 换算。
- **每个地址空间都要保留内核可运行环境。** 任务页表映射 FDT RAM 的高半区直接映射、内核段及共享内核栈；切换 `satp` 后，内核仍能访问自身代码、堆、页表和任务栈。

## 实现范围

- 新增 `kernel::memory::address`，集中定义直接映射基址、物理地址到高半区虚拟地址换算，以及内核映像 VMA 到 LMA 的换算。该模块只做地址计算，不依赖页帧分配器或页表；使用者负责确保映射已经建立。
- 引导页表仍由 `boot.S` 在 Rust 启动前建立。QEMU `virt` 当前启动配置使用一个 1 GiB 高半区叶子映射覆盖 RAM，因此启动期间解析 FDT、清零页帧、初始化堆和建立第一张任务页表时都可以使用高半区指针。
- 每张任务页表把 FDT 描述的 RAM 逐页映射到高半区直接映射窗口，权限为 `SRW-`；随后内核 `.text`、`.rodata`、`.data` 和 `.bss` 的段映射覆盖对应页权限。任务页表不再建立 RAM 低地址恒等映射。
- 页帧分配器清零物理页时先换算成高半区指针。堆以高半区虚拟地址管理对象，同时保留 `PhysicalFrameRun` 作为后备页的物理所有权记录。
- 页表根页、子页表和日志遍历通过高半区直接映射解引用；PTE 编码、地址空间根记录和 `satp` 仍使用物理地址。
- FDT 入口及用户程序固定加载槽位仍以物理地址传入或记录，在读取、清零和复制时换算为高半区指针。用户程序自身继续映射到低半部共同入口 `0x40000000`。
- UART MMIO 不是普通 RAM，本阶段仍按设备物理范围单独建立低地址映射；不把设备地址送入 RAM 直接映射换算。

## 边界与限制

- 启动阶段的临时页表仍采用 QEMU `virt` 的固定 1 GiB 粗粒度高半区映射，并保留低地址映射，以便低地址 `_start` 完成页表切换。当前受支持启动配置为单 hart、128 MiB RAM；尚未建立适配任意物理内存布局的早期映射器。
- 内核直接映射覆盖 FDT 报告的 RAM，而非设备 MMIO。页帧分配器仍按 FDT 范围排除内核、DTB 和固件保留区域。
- 本阶段没有引入物理地址 newtype、按需映射、ASID、SMP TLB shootdown、页保护空洞或高半区链接布局之外的内核内存模型。
- 用户指针访问仍通过现有 syscall 范围校验和 `SUM` 局部窗口；本阶段不改变用户态访问策略。

## 验收方式

1. `make fmt-check` 和 `make build` 成功。
2. `make run` 启动后，堆自检、全局分配器自检、页帧分配器自检通过，并进入用户态 shell。
3. shell 的 `help` 能正常响应；任务页表调试输出中，RAM 映射位于 `0xffffffc0...`，且不再出现 RAM 的低地址恒等映射。
4. 批处理启动时，用户程序仍可读取自身镜像、通过 UART 输出，并在异常任务退出后继续调度其他任务。

## 后续连接

页帧、堆、页表和 FDT 已遵循物理地址与内核虚拟地址分离的接口。后续可以收紧临时启动页表的固定 1 GiB 映射：先由 FDT 解析出 RAM 范围，再设计足以访问内核、FDT、页表和早期堆的最小启动映射，同时保证切换过程中的取指、栈和陷入入口有效。
