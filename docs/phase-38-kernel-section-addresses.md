# 第 38 阶段：分开描述内核段虚拟地址与物理地址

## 目标关联

第 37 阶段已在任务页表中为内核段建立高地址别名，但地址空间输入仍只有一个段起点，并隐含假设“链接地址就是物理地址”。后续若把内核主体改为高地址 VMA、低地址 LMA，页表必须明确知道两者的对应关系。本阶段把这项关系写进内核段映射接口。

## 学习重点

页表映射的基本输入是虚拟地址、物理地址和长度。链接器给出的运行时地址（VMA）与加载地址（LMA）表达不同含义；当前 ELF 恰好让它们相等，不应因此把概念合并。

## 实现边界

- `KernelSectionRange` 显式保存 `virtual_start`、`physical_start` 和有效字节数 `size`。
- 内核段映射按虚拟页递增，同时映射到对应物理页；高别名则按 `KERNEL_VIRTUAL_BASE + physical_address` 计算。
- 若段虚拟地址本身就是该高别名，避免重复安装同一个叶子映射。
- 现有链接器符号仍是低地址符号；调用方暂时把它们同时作为虚拟起点和物理起点。因此运行行为保持不变，ELF 仍要求 VMA=LMA。
- 本阶段不修改 linker script、ELF 装载布局、启动入口或 `satp` 切换，也不切换内核执行地址。

## 验收方式

- `make build` 成功。
- `make inspect-kernel-elf` 仍验证 ELF 入口和当前 VMA=LMA 基线。
- QEMU shell 启动后可执行 `help`；调试页表应继续显示内核低地址映射和映射到相同物理页的高别名。

## 后续连接

实现真正的高 VMA、低 LMA 前，还需在链接脚本中为低地址入口和高地址主体划分加载布局，并让启动代码在启用合适页表后切换到高地址。届时启动/任务页表构建方必须从链接器提供的 VMA 与 LMA 分别填充本接口；不能再把同一符号复制到两个字段。
