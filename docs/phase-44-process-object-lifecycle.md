# 第 44 阶段：进程对象与退出资源回收

## 目标关联

上一阶段取消了固定进程数量上限，但内核记录仍主要是调度索引，资源散落在多处全局状态中。要实现用户可调用的 `fork` 类创建，内核首先需要有一个明确的进程对象，能说明进程拥有哪些资源、创建失败时如何回滚、退出后由谁回收。

本阶段建立该对象和生命周期，保留 shell 与批处理的启动方式。它为后续 `clone`/fork 创建新进程提供统一的资源容器，并确保当前 `exit` 和异常结束路径能归还资源。

## 实验问题

**进程退出后，内核何时可以释放其地址空间、用户内存和内核栈？**

进程退出并不代表 CPU 已经离开该进程的内核栈。必须先切换到另一进程的地址空间，且不能在仍使用旧栈时释放旧栈。最后一个进程退出时，也必须有不属于该进程的栈和页表可供回收代码运行。

## 实现范围

- 将调度记录重命名并整理为 `process::Process`、`ProcessId` 和 `ProcessState`。
- 每个进程通过 `ProcessResources` 集中拥有独立地址空间、用户程序镜像、用户栈和内核栈；陷入帧固定保存在内核栈顶下方，按栈布局推导其地址，不另存指针。
- `creation` 先预留进程容器容量并准备全部资源，成功后才发布进程对象；局部资源所有者和地址空间创建器负责失败回滚。
- `AddressSpace` 作为显式所有权值从创建器传给进程对象；删除 memory 内部用全局数组索引管理根页表的路径。
- 进程退出后，调度器先切换到下一个进程页表，再释放旧页表、镜像和用户栈。旧内核栈放入单项延迟释放槽，并在另一进程的 trap 栈上释放。
- 最后一个进程退出时，在其陷入处理仍可访问的启动栈映射中切换到独立引导栈，再激活保留的引导页表；完成切换后才回收该进程的全部资源并进入空闲等待。
- 当时的 shell 模式和批处理模式共用单进程创建器；后续 batch 启动入口已移除，当前内核只创建入口进程，其余进程由用户态按需派生。

## 资源所有权与销毁顺序

```text
Process
└─ Option<ProcessResources>
   ├─ AddressSpace：独占页表树
   ├─ TrapFrame 地址：位于该进程的内核栈 backing 中
   ├─ LoadedUserProgram：拥有用户镜像页帧
   ├─ UserStack：拥有用户栈页帧
   └─ KernelStack：拥有连续内核栈页帧
```

正常进程切换后的退出回收顺序：

```text
保存退出状态 → 切换当前进程索引和页表 → 拆除旧进程页表
→ 归还镜像页与用户栈页 → 暂存旧内核栈
→ 在另一进程的陷入栈上归还旧内核栈
```

最后一个进程退出时，回收器把执行栈切到内核启动栈，并将 `satp` 切回引导页表。此后旧进程的页表、镜像、两种栈都不再被执行路径使用，才一次性销毁。

进程记录暂时保留在 `Vec<Process>` 中。其 `resources` 变为 `None`，状态和退出码仍保留；ID 追加分配且不复用。这给后续父进程收集退出状态留下清楚的对象边界，但本阶段还没有父子关系或 `wait`。

## 本阶段不实现

- 不增加运行时 `fork`/`clone`、`exec`、`wait` 或 shell `run` 命令。
- 不引入 PID 复用、僵尸进程收集、引用计数或复杂的任务状态机。
- 不改变批处理调度策略，也不增加多 hart 并发。
- 不声称支持 Linux 的 fork 行为；目前仍只有已经实现的 `write`、`read`、`clock_gettime`、`exit` 和 `sched_yield` 等具体 syscall 行为。

## 验收方式

```sh
make fmt-check
make build LOG_LEVEL=info
make run LOG_LEVEL=info
```

运行中观察：

1. init 启动 shell；在 shell 中运行程序名会创建子进程并由定时器调度。
2. `exit` 和用户异常会结束当前进程；日志显示切换后回收页表、镜像和栈资源。
3. 最后一个进程结束时，内核切换到引导回收上下文并进入空闲等待，不再恢复已退出的用户态现场。
4. 进程创建路径先构造完整资源，再追加 `Process` 记录；所有资源由该对象单点持有。
