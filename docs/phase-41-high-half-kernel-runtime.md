# 第 41 阶段：从低地址启动并在高半区运行内核

## 目标关联

任务页表和陷入入口已经能够使用内核高地址别名，但内核 ELF 仍在低地址链接。要让地址空间规划真正成为内核运行约定，启动代码必须先在低地址建立页表，再切换到高地址执行 Rust 初始化；否则链接器生成的全局地址、函数地址和栈地址仍会要求低地址映射长期存在。

本阶段完成这条启动纵向路径，为后续把物理内存访问从低地址恒等映射迁移到明确的物理内存映射提供可运行基础。

## 学习重点

- **VMA 与 LMA 的职责不同。** 内核主体的 VMA 是运行时高半区地址；LMA 是 OpenSBI/QEMU 将字节放入 RAM 的低物理地址。链接器用 `AT` 为各段分别指定两者。
- **低地址入口是启动跳板。** `_start` 仍位于 `0x80200000`，它用低地址符号清理启动存储、准备临时页表，然后显式跳到 `kernel_main` 的高地址。
- **切换地址空间必须同时考虑取指和数据。** 启用 `satp` 后，当前指令、`stvec`、`sp`、`gp`、FDT 指针及 UART 都必须仍可访问。
- **任务页表承接启动期契约。** 启动页表只负责早期跳转；进入用户任务前切换到任务页表。任务页表保留高地址内核段、共享 S-mode 栈和低地址 RAM 恒等映射。

## 实现范围

- `linker.ld` 将 `.text.entry` 和引导存储留在低地址；Rust 内核 `.text`、`.rodata`、`.data`、`.bss` 的 VMA 设置为 `0xffffffc000000000 + LMA`。ELF 入口仍是低地址 `_start`。
- 引导页表和 16 KiB 引导栈放在低地址启动 BSS。`boot.S` 清零引导 BSS 与内核 BSS 的物理装载范围，再建立 1 GiB 叶子映射：低地址设备区、QEMU RAM 恒等映射及 RAM 高半区别名。
- 启用 Sv39 后，汇编把 `stvec`、`sp` 和 `gp` 切换到高地址，再由低 LMA 符号计算 `kernel_main` 的高 VMA 并跳转。`a0`/`a1` 的 hart ID 和 FDT 物理地址保持不变；FDT 仍通过 RAM 恒等映射读取。
- 每个任务页表按高 VMA、低 LMA 映射内核段并应用原有页权限。引导栈在启动调用链结束前继续映射；所有任务内核栈在每张任务页表中共享映射，保证调度器切换 `satp` 后仍能在旧陷入栈上完成剩余工作。
- 页帧分配器和用户程序装载器需要物理地址时，从高半区符号减去固定偏移得到 LMA。低地址 RAM 恒等映射暂时继续服务堆、页表页、FDT、用户镜像槽和设备访问。
- `make inspect-kernel-elf` 检查低地址入口、启动段恒等布局以及内核主体的高 VMA/低 LMA 固定偏移关系。

## 暂不实现

- 临时启动页表按 QEMU `virt` 的 128 MiB RAM 约束使用 1 GiB 叶子映射，并额外覆盖低地址设备窗口；它不是通用物理内存映射器，也不按 FDT 动态裁剪权限。
- 任务页表仍把 FDT RAM 低地址恒等映射为 S-mode 可读写；堆和物理页帧的 Rust 指针仍使用低地址。
- 用户程序仍运行于低半部 `0x40000000`，用户镜像继续装入固定物理槽位；本阶段不实现 ELF 用户程序加载、动态任务创建或 Linux ABI 扩展。
- 仍是单 hart 启动。未加入多 hart 引导、ASID、TLB shootdown、内核栈保护页或通用直接映射窗口。

## 验收方式

1. `make build` 成功。
2. `make inspect-kernel-elf` 报告入口 `0x80200000`，启动段 VMA=LMA，内核主体 VMA 位于 `0xffffffc0...`，且 `VMA - 0xffffffc000000000 = LMA`。
3. `make run` 能完成启动、打印高半区内核段范围并进入用户态 shell；输入 `help` 后 shell 正常响应。
4. `make run BOOT_MODE=batch BATCH_EXCLUDED_BINS=shell` 中，计算、协作、CPU 密集、I/O、非法指令和非法内存访问任务都按预期运行或终止，最终报告所有任务退出。

## 后续连接

内核代码和栈已经可以在高半区运行，任务页表仍保留 RAM 低地址恒等映射。下一步应聚焦物理地址如何被内核访问：明确一个按 FDT 范围建立的内核直接映射接口，并逐步让页帧、堆和设备访问从裸物理地址指针迁移到显式映射地址。之后再收紧启动阶段的粗粒度映射，并评估是否需要把用户镜像和内核物理内存访问进一步分离。
