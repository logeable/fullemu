# 第 2 阶段：FDT 头部校验（阶段记录）

## 目标

OpenSBI 会把 FDT 地址通过 `a1` 交给内核。此前内核只打印该地址；本阶段从这个地址读取固定头部，校验格式标记、版本、总长度和主要区块边界，然后打印头部摘要。

FDT 头部由 32 位大端字段组成，包含 `magic`、`totalsize`、区块偏移和长度等信息。本阶段读取 40 字节的版本 17 头部；接受版本 17 及更新且向后兼容版本 17 的格式。参见 [Devicetree 规范：Flattened Devicetree 格式](https://devicetree-specification.readthedocs.io/en/v0.2/flattened-format.html)。

## 实现范围

- 本阶段的实现只解析 40 字节头部并验证范围；后续的结构块遍历见[第 3 阶段](phase-3-fdt-structure-walk.md)。
- 头部解析器接收字节切片，是不依赖硬件的纯函数；从固件地址读取头部的 `unsafe` 边界单独封装在 `read_from_ptr` 中。
- 启动时校验 FDT。格式无效时打印具体错误并进入现有 panic 停机路径；有效时打印版本、总长度、结构块和字符串块信息。
- 不改变当前 UART 地址，也不解析 `/memory`、`/chosen` 或任何设备节点。
- 不引入第三方依赖。

## 验证

在宿主机运行纯解析器测试。Makefile 会从当前 Rust 工具链读取宿主机 target：

```sh
make test-fdt
```

在 QEMU 中读取 OpenSBI 传入的真实 FDT：

```sh
make run
```

正常启动信息之后应出现 FDT 版本、总长度、结构块偏移/长度和字符串块偏移/长度。宿主机测试覆盖有效头部、短输入、错误 magic、无效总长度、不支持的版本，以及保留表、结构块和字符串块越界。

## 本阶段结束时的限制

- 只校验头部声明的主要区块边界，不检查区块重叠，也不读取区块内容。
- 当前支持版本 17 头部布局及向后兼容该布局的更新版本；更早版本会明确拒绝。
- DTB 指针本身由固件提供；内核在形成字节切片前无法仅凭地址证明该内存映射有效。
- UART 仍固定使用 QEMU `virt` 的已知地址。设备发现和物理内存范围解析留待后续小阶段。
