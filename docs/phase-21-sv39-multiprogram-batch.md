# 第 21 阶段：Sv39 下的多道程序批处理入口

> 当前状态：本阶段的 batch 启动模式已移除。本文保留当时的设计和实验记录，不再提供可用于当前代码的 batch 构建命令；当前由内核启动单个 init 或指定入口程序，再由用户态按需创建进程。

## 目标关联

Sv39 已为单个用户任务建立内核/用户页面权限边界。本阶段保留默认交互式 shell，同时增加一个多道批处理启动入口，让多个已构建程序同时驻留并由现有定时器调度。这为后续从 shell 动态创建任务提供任务初始化和调度复用基础；本阶段不实现动态创建、等待或地址空间隔离。

## 实验问题

**现有任务现场和定时器调度能否在 Sv39 下同时运行多个用户程序？** 批处理入口为每个程序建立独立的静态任务现场、用户栈和内核陷入栈，再用一张页表映射所有程序镜像与用户栈。所有用户任务仍共享同一虚拟地址空间。

## 实现范围

- 当时的 `FULLEMU_BOOT_MODE` 选择单程序 shell 启动或多程序 batch 启动；多程序启动列表由构建清单决定。
- 当时的 `run_batch_programs` 入口依次装入清单中的程序，为每个任务准备独立陷入现场和 16 KiB 用户栈，然后启动已有的协作与定时器抢占调度器。
- Sv39 页表初始化接收多个用户栈和镜像范围，并为它们设置 U-mode 权限。页表根仍只有一份，因此批处理任务之间可以访问其他任务映射的用户页面；这不是任务隔离。
- 当时默认不把 `shell` 放入批次，因为它的 `read` 在内核态轮询等待输入，会阻塞 S-mode 调度路径。后续引入 init、动态进程创建和 shell 前台执行后，batch 启动路径不再承担实际功能，已从当前实现中移除。
- 用户 bin 名以 `disabled-` 开头时，`user/build.rs` 不将其加入布局和镜像清单；`make build-user` 也不把它作为 Cargo bin 目标构建。这样的源码仍留在 `user/src/bin/`，便于暂时禁用实验程序。
- 禁用前缀约定通过仓库的 `make build-user` 生效；直接运行 Cargo 的 `--bins` 会绕过 Makefile 的目标筛选，仍按 Cargo 自动发现规则构建这些 bin。
- 批处理程序中发生用户异常时，内核记录异常原因，将任务标记为 `Exited` 并继续调度其他就绪任务。当前不保留单独的异常终止状态；所有批处理任务退出后，内核进入等待状态。

## 暂不实现

- shell 尚不能创建新任务；本阶段的任务集合在进入 U-mode 前一次性确定。
- 没有父子任务关系、阻塞 `wait`、退出状态回收或同一程序的多个并发实例。
- 所有任务共享同一 Sv39 根页表，程序镜像槽位和用户栈对批次中的所有 U-mode 程序可见。
- 批次集合由构建清单决定，不支持命令行参数或从文件系统加载程序。

## 运行与验收

当时的验收通过启动多个用户程序，观察定时器抢占、协作让出和异常退出。当前可运行 `make run` 启动 init 与 shell，再输入 `compute`、`io` 等程序名，观察单个子进程运行结束后返回 shell；调度机制仍由这些进程路径使用。

验证禁用 bin 时，可暂时将一个用户程序源文件改名为 `disabled-<原名>.rs` 后运行 `make build-user`；它不应出现在布局文件和镜像清单中，也不应作为 Cargo bin 目标构建。

## 后续连接

本阶段证明现有调度器可以管理一组预先确定的多道任务，但没有任务创建和资源回收接口。下一步应先决定如何在不引入文件系统的情况下由 shell 指定已嵌入程序，再实现受限的任务创建和等待；每任务独立页表与动态物理页分配仍需单独设计。
