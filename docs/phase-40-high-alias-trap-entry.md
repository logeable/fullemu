# 第 40 阶段：从高地址别名进入 S-mode 陷入入口

## 目标关联

第 37 阶段给内核段建立了高地址别名，第 39 阶段让映射接口显式消费链接器 LMA。本阶段在任务页表启用后，把 `stvec` 指向陷入入口的高地址别名，验证 CPU 能从该别名取指并完成真实的 syscall 和定时器陷入路径。

## 学习重点

页表可以让同一段指令在低地址和高地址都可访问。设置 `stvec` 只改变陷入发生时 CPU 从哪里开始取指，不会自动改变当前正在运行的内核代码地址、栈地址或全局数据指针。

## 实现边界

- 首个任务页表激活后，计算 `supervisor_trap_entry` 对应的高地址别名，并把它写入 `stvec` 直接模式入口。
- 所有任务页表都映射相同的内核高地址 `.text`，所以调度时切换 `satp` 后该 `stvec` 仍有效。
- trap 汇编进入 Rust 前会重新设置 `gp`；trap frame 和任务内核栈继续使用 RAM 的低地址恒等映射。
- 当前 VMA=LMA，所以链接器给出的 `supervisor_trap_entry` 地址可直接作为物理地址计算高别名。若未来分开 VMA/LMA，必须先按 `.text` 的 VMA 范围与 LMA 起点把符号地址换算成物理地址。
- 不改 ELF 布局、启动入口、常规内核执行地址或用户地址空间布局；不声称已完成高半区迁移。

## 验收方式

- `make build` 成功，格式检查和差异空白检查通过。
- `make run LOG_LEVEL=debug` 应打印高地址陷入入口；shell 启动后执行 `help`，确认 syscall 经该入口返回。
- `make run LOG_LEVEL=info` 后输入 `cpu_hog`，应能观察到用户程序持续占用 CPU 时仍由定时器进入高地址陷入入口并恢复 shell。

## 后续连接

本阶段确认现有高别名可承载实际陷入入口。下一步应进一步明确内核函数在高别名执行时的链接重定位、`gp` 和指针约定，再考虑低地址启动 trampoline 与高 VMA 内核主体；不应直接把整个 Rust 内核搬到高地址而遗漏启动期仍需访问的对象。
