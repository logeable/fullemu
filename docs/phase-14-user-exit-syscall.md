# 第 14 阶段：Linux RISC-V `exit` 系统调用

## 目标关联

用户程序已有 `write`，但还不能通过内核接口正常结束。`exit` 补齐最小程序运行路径中的终止操作，为后续加载多个用户任务、等待子任务和运行 shell 建立明确的任务生命周期边界。

## ABI 约定

Linux RISC-V 使用通用系统调用编号 `93` 表示 `exit`。调用约定与 `write` 相同：系统调用号放在 `a7`，第一个参数放在 `a0`，通过 `ecall` 进入 S-mode。参数在 Linux 接口中是 C `int` 状态码；内核只保留低 8 位作为正常退出码。`exit` 不返回用户态。[Linux RISC-V 系统调用编号](https://github.com/torvalds/linux/blob/master/include/uapi/asm-generic/unistd.h)、[Linux 内核退出路径](https://github.com/torvalds/linux/blob/master/kernel/exit.c)。

## 实现范围

- 内核 syscall 分发器识别编号 `93`，将 `a0` 转换为 `i32` 并保留低 8 位，产生“结束当前任务”的结果，而不伪装成普通返回值。
- 陷入处理器区分可返回系统调用和任务终止结果。`exit` 分支记录状态码，不递增用户 `sepc`，不恢复原 U-mode 陷入帧。
- 当前只有一个静态用户任务且没有调度器。因此内核记录退出并进入等待循环；没有其他任务可切换，也没有父任务可接收等待状态。
- 用户态封装 `syscall::exit(status)` 将状态码传入 `a0`、编号 `93` 传入 `a7`，并声明为不可返回。用户程序先调用 `write`，再调用 `exit(0)`。

## 暂不实现

- 当前未实现 `exit_group`（编号 `94`）、线程组、父子进程关系、`wait`/`wait4`、僵尸任务回收或退出资源清理。
- 当前任务模型只有一个用户任务；内核等待循环表示该任务已停止执行，不等同于完整 Linux 进程退出和状态回收语义。
- 内核记录传入的 `i32` 状态参数；尚无父进程可观察 Linux `wait` 编码后的退出状态。

## 运行与验收

```sh
make fmt-check
make build
make run
```

QEMU 串口应先显示用户程序的 `write` 文本，随后显示状态码 `0` 的退出信息和“当前尚无其他可调度任务”的说明。此后用户程序不再执行，内核停留在等待循环。QEMU 运行命令可由外部超时结束。

## 后续连接

后续引入任务调度后，退出路径可把当前任务标记为已结束并切换到另一个可运行任务；再建立父子关系和等待机制，才能让 shell 通过退出状态管理外部命令。
