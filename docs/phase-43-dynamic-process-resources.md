# 第 43 阶段：动态进程资源与镜像页

## 目标关联

当前任务容器、批处理入口和用户镜像加载器都把容量固定为 8。这个限制会在实现 `fork` 前阻止内核按物理资源创建子进程，也让镜像槽的生命周期脱离页帧分配器。本阶段让任务和镜像数量随可用堆与页帧资源增长，为后续复制进程地址空间、并在 `exit` 后回收进程资源建立基础。

## 实验问题

**任务数量由什么决定？** 内核应由实际可分配的页帧和内核对象内存决定是否能创建任务，而不是由固定数组或固定镜像槽位决定。

## 实现范围

- 删除构建脚本的 8 个镜像数量上限，删除内核链接脚本中的固定镜像加载区和用户链接脚本的 64 KiB 槽位断言。
- 装载每个用户镜像时，按镜像字节数向上取整，向页帧分配器申请清零后的物理页，并复制镜像内容。
- `LoadedUserProgram` 拥有镜像页帧；任务创建失败或任务资源释放时，镜像页帧回到页帧分配器。
- 页表按镜像页帧逐页建立用户映射；镜像的物理页可以不连续，用户程序仍链接到共同虚拟入口 `0x40000000`。
- 删除任务数为 8 的检查；批处理索引、任务记录和启动时共享内核栈映射均使用可失败预留的 `Vec`。
- 不增加 `fork`、`exec`、`wait` 系统调用或 shell 命令；本阶段只处理为进程创建和退出打基础的资源所有权与数量上限。

## 资源生命周期

```text
构建清单中的静态镜像字节
  → 分配并清零镜像页帧
  → 复制字节并建立该任务的用户映射
  → 任务持有镜像、两种栈和独立地址空间
  → 退出后切换到其他地址空间
  → 销毁页表并归还镜像页、用户栈页和内核栈页
```

构建清单只列举可运行程序，不再预先为每个程序划分物理槽。用户镜像计数没有代码中预设的固定上限；批处理同时装入所有清单程序，仍可能因物理内存、页表页或内核堆耗尽而失败。清单中的原始镜像仍嵌入内核构建产物，因此构建产物大小也受工具链和目标内存容量约束。

镜像的字节长度用于 syscall 缓冲区范围校验；映射长度按页向上取整。页帧由任务资源所有者保留，地址空间只借用页帧建立映射，不负责释放映射目标。

## 验收方式

```sh
make fmt-check
make build
make run LOG_LEVEL=info
```

当前启动应进入 init 和 shell；输入程序名可按需创建进程。增加嵌入式镜像不再遇到 8 项构建上限；超出可用运行资源时应通过现有任务创建错误路径报告失败，而不是覆盖相邻镜像槽。批量启动清单的旧行为已移除。

## 当前限制与后续连接

- 任务记录追加后 ID 不复用；当前仍是启动期创建，没有运行时 fork。
- 用户任务仍以单线程执行上下文表示；尚无父子关系、子进程返回值或退出状态回收协议。
- 任务地址空间创建失败会由地址空间模块回滚页表树；任务创建过程中已经取得的镜像与栈资源由局部所有者释放。
- 当前调度器只会在切换到另一个就绪任务后回收刚退出任务；最后一个任务退出时内核停在等待循环，因此其活动内核栈和地址空间仍保留到复位。后续进程退出实验必须提供安全的回收上下文，覆盖最后一个进程退出的路径。
- 页帧分配器的空闲范围元数据和 FDT 区域数量仍有内部固定容量；它们是内存拓扑元数据上限，不是用户镜像数量或任务数量上限。

后续的第 44 阶段先明确了 `Process` 对象及退出资源回收顺序，为 fork 类创建建立资源所有权基础。当前 RISC-V Linux ABI 使用 `clone` 系统调用承载 fork 类创建，不应宣称存在独立的通用 `fork` syscall。`exec`、`wait`、线程共享标志、写时复制和 shell 命令仍不属于第 43 阶段。
