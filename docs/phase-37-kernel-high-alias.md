# 第 37 阶段：为内核段建立高地址别名

## 目标关联

第 36 阶段确认当前 ELF 的入口、VMA 和 LMA 都在低地址。本阶段开始准备高半区迁移：让实际启用的任务页表同时提供内核低地址映射和高地址别名，为未来把内核主体链接到高地址提供映射基础。

## 学习重点

一个物理页可以同时对应多个虚拟地址。当前内核仍以低地址链接和运行；新增别名 `KERNEL_VIRTUAL_BASE + physical_address`，其中 `KERNEL_VIRTUAL_BASE = 0xffffffc000000000`。例如物理页 `0x80200000` 的高地址别名为 `0xffffffc080200000`。此阶段只创建映射，不通过别名执行代码。

## 实现边界

- 每个任务页表继续保留原来的 RAM 低地址恒等映射和内核低地址段权限。
- 对 `.text`、`.rodata`、`.data`、`.bss` 的物理页额外建立高地址映射，权限分别保持 `SR-X`、`SR--`、`SRW-`、`SRW-`。
- 本阶段依赖当前链接布局中内核段 VMA=LMA，因此把链接段地址同时作为物理地址。高地址别名的计算和映射集中在 `memory::address_space`。
- 不映射整段 RAM 到高半区；只映射当前内核映像的四个段。
- 不改变 `_start`、链接脚本、`satp` 切换、`gp`、`sp`、`stvec`、陷入帧或物理页访问方式。高地址尚未成为内核执行地址，也没有实现启动 trampoline。

## 验收方式

- `make build` 成功。
- 使用 `make run LOG_LEVEL=debug` 观察首个任务页表日志：内核低地址段仍存在，高地址范围应显示 `0xffffffc000000000 + 物理地址`，并映射到相同的物理页范围及对应段权限。
- shell 启动后仍可执行 `help`；batch 模式下现有用户程序仍可运行。该验证确认新增映射没有覆盖用户区或破坏原低地址执行路径。

## 后续连接

下一阶段可将链接器布局拆为低地址 trampoline 和高地址内核主体，并明确高 VMA 对应的低 LMA。届时地址空间创建接口必须同时接收每个内核段的虚拟范围和物理装载范围；不能再假定链接符号地址就是物理地址。
