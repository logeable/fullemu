# 第 53 阶段：用户进程 program break 与堆页

## 目标关联

用户程序目前只能使用 ELF 映像和固定大小的用户栈，无法从内核取得额外的可写内存。动态内存是后续在用户运行库中实现 `Box`、`Vec` 等容器的基础。本阶段先让内核为每个进程管理一段可增长、可缩小的用户堆。

## 学习重点

- 内核堆为内核对象提供字节分配；用户堆属于某个进程的虚拟地址空间，两者的映射、所有权和用途不同。
- Linux RISC-V 原始 `brk` 系统调用号为 214。它设置进程 program break；成功返回新边界，失败返回当前边界。
- program break 是逻辑边界，页表按 4 KiB 页映射。堆边界在页内移动时不改变映射；跨页增长时才分配页帧，缩小时只回收完整越过边界的页。
- 页表管理虚拟到物理映射，进程资源对象拥有堆数据页帧。建立映射不会转移物理页帧所有权。

## 实现范围

- 用户堆起点取 ELF 用户映像末端；当前 ELF 映像大小按页对齐，堆向高地址增长，用户栈仍从地址空间高端向下使用。
- `process::user_heap::UserHeap` 记录堆起点、当前 program break 和已分配页帧。
- 在 syscall 层实现 Linux RISC-V `brk` 原始调用：地址为零时查询当前边界；无效范围或资源不足时返回旧边界。
- 堆增长时先为本次扩展分配并清零所有页帧，再建立 `URW-` 映射；成功后才将页帧和新 break 纳入进程资源。
- 堆缩小时先清除被释放页的 PTE、刷新当前 hart 的 TLB，再把页帧归还分配器。新扩展不能越过用户栈起点。
- 用户指针范围校验将当前已映射堆页纳入可读写范围，允许 syscall 缓冲区、`execve` 参数和 `wait4` 状态位于用户堆。
- `fork` 为子进程复制堆页和 break；`exec` 使用新映像末端创建空堆；进程退出时回收堆页帧。
- 用户库提供原始 `brk` 调用封装，`heap_test` 覆盖跨页读写、非法扩展、fork 隔离、缩小回收和重新分配清零。

## 暂不实现

- 用户态 Rust 全局分配器、`alloc` crate、`Box`、`Vec`、`malloc` 或 `sbrk` 包装。
- `mmap`/`munmap`、懒分配、缺页时分配、写时复制、地址空间随机化或 guard page。
- 堆与文件映射的通用区域管理、并发多 hart、内存限额和过量提交策略。

## 模块边界

`syscall` 负责识别 Linux `brk` ABI；`process::user_heap` 管理当前进程的 program break、页帧所有权及增长/缩小顺序；`memory::address_space` 只负责建立或清除用户叶子映射，不释放映射目标页帧；`frame_allocator` 提供和回收清零物理页。`fork`、`exec` 和进程退出分别复制、替换和释放堆资源。用户态运行库只封装原始 syscall，不参与页表和页帧管理。

## 验收方式

```sh
make fmt-check
make build
make run
```

在 shell 输入 `heap_test`。程序应报告用户堆验证通过，并以状态码 0 返回 shell。它验证扩展后能访问多个页、无效地址请求保留旧 break、fork 后父子堆页独立、缩小后页帧可重新分配且内容为零。

## 后续连接
