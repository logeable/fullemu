# 第 26 阶段：地址空间页表回收

## 目标关联

Sv39 页表已经从物理页帧池按需取得根页和中间页，但此前任务结束后页表页仍永久占用页池。回收非活动任务的页表，为任务退出后的资源复用建立基础，支撑后续 shell 动态启动程序。

## 实验问题

**任务退出后，内核如何确认它的地址空间已不再被硬件使用，并只归还页表自身拥有的页帧？**

## 实现范围

- 页帧分配器提供仅供页表子系统使用的地址归还接口。该接口验证地址属于页池且当前已分配；调用方还须证明页表树独占该页帧。
- `memory::destroy_address_space` 只允许销毁非当前活动地址空间。它先验证页表树，再递归归还根页表和中间页表页，成功后清空地址空间索引槽位。
- 销毁过程只回收非叶子 PTE 指向的页表页，不释放叶子映射指向的内核区域、用户栈、UART 或用户程序镜像。
- 调度器切出一个已经退出的任务并激活下一个任务的地址空间后，再销毁旧任务的页表。这样不会释放当前 `satp` 正在使用的页表。
- 保持固定任务数组和当前批处理模式，不实现任务槽复用、`wait` 或动态用户栈。

## 暂不实现

- 若没有其他就绪任务，当前任务退出后内核会进入等待循环；由于没有独立的内核页表可供切换，当前活动地址空间保留，不尝试销毁它。
- 页表建立中途失败仍是启动致命错误，不回滚已经分配的页表页。
- 任务描述、内核栈、用户栈和程序镜像的回收不属于本阶段。
- 页帧池仍固定放在内核 BSS，不扫描 FDT，也不回收固件保留区域。

## 运行与验收

```sh
make fmt-check
make build
make run BOOT_MODE=batch LOG_LEVEL=info
```

QEMU 日志应显示任务退出或异常后先切换到另一地址空间，再报告旧任务释放的页表页数量。批处理中的其他任务应继续运行；最后一个任务退出时内核进入等待状态，其活动页表不会被释放。

## 后续连接

在页表树可以安全销毁后，后续实验可以加入任务槽复用与动态任务创建，并逐步把用户栈从静态数组迁移到页帧分配器。
