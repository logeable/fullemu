# 第 7 阶段：CPU 虚拟化的饥饿对照

本阶段记录的是第 8 阶段协作式调度实现之前的基线。当前默认启动已运行协作式切换；本阶段用于比较“没有调度器”和“任务主动让出”这两种行为。

## 问题

只有一个 hart 时，如果任务 A 持续运行且不主动让出 CPU，任务 B 怎样才能继续运行？本阶段先建立没有调度器时的基线，观察操作系统尚不能共享 CPU 的结果。

## 实验范围

- 基线版本的 `main` 依次调用任务 A 和任务 B，没有任务队列、上下文切换或定时器抢占。
- 任务 A 永不返回，也不主动让出 CPU；它定期报告自己的运行计数，证明 hart 仍由 A 占用。
- 任务 B 若获得执行机会，会定期报告心跳。基线中它位于 A 之后，预期永远不会开始。
- 当前只有一个 hart；A、B 使用同一个内核地址空间。本阶段不建立完整进程抽象，也不提供内存隔离。

## 运行与验收

以下命令与结果对应基线提交 `b24db52`。当前分支默认运行第 8 阶段的协作式调度，输出会不同。

```sh
make build
make run
```

启动信息结束后，应看到任务 A 的开始提示及持续增长的运行计数；不应看到任务 B 的心跳。该输出说明直接执行允许 A 持续占用 CPU，而当前内核没有机制让 B 获得进展。

## 后续问题

第 8 阶段引入了显式让出和协作式上下文切换；后续再通过定时器抢占验证内核能否在 A 不配合时收回 CPU 并调度 B。
