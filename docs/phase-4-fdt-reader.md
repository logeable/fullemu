# 第 4 阶段：FDT 完整格式读取器

## 目标

把前一阶段的 token 遍历器扩展为可复用的 DTB 只读读取器：校验 FDT 版本 17 布局和区块边界，读取内存保留表，验证节点与属性顺序，并通过借用切片暴露属性原始值。该读取器不申请堆内存，也不解释平台设备 binding。

实现依据为 [Devicetree 规范：Flattened Devicetree 格式](https://devicetree-specification.readthedocs.io/en/v0.2/flattened-format.html)，其中定义了 40 字节头部、内存保留表、结构 token、字符串块以及节点属性顺序。

## 接口与实现范围

- `FdtBlob::parse` 接受完整 DTB 切片，检查头部、总长度、内存保留表的 8 字节对齐、结构块的 4 字节对齐，以及头部和各区块互不重叠。字符串块本身没有对齐要求。
- 内存保留表以 64 位大端地址/长度对表示；读取器检查终止项、地址加长度溢出和区间重叠。`memory_reservations` 返回借用式迭代器。
- `FdtBlob::structure` 返回 token 事件遍历器。属性事件包含 DTB 内原始值的借用切片，不复制属性内容。
- 结构遍历器检查节点配对、唯一根节点、属性先于子节点、区块边界和 `FDT_END` 位置。为避免无堆分配内核中的递归或动态栈，节点深度最多 64 层，超过时返回明确错误。
- 保持无第三方依赖。通用解析器只解释 FDT 二进制格式；`/memory`、`/chosen`、`/cpus` 的含义和设备 binding 留给后续平台层。
- 节点名和属性名当前限制为 ASCII。属性值填充只检查范围并跳过：QEMU 10.2.2 的 `virt` DTB 在属性对齐字节中出现非零值。规范描述这些填充为零，因此这是为首要模拟器做的兼容放宽；节点名填充仍严格检查为零。

## 验证

```sh
make test-fdt
make build
make run
```

宿主机测试覆盖内存保留表读取、缺少终止项、区块重叠、保留范围重叠、借用属性值、节点属性顺序，以及此前的头部和 token 边界错误。QEMU 启动应完成完整 DTB 结构遍历并输出节点和属性摘要。

## 当前限制

- 只支持版本 17 头部布局，以及声明向后兼容版本 17 的新版本；版本 16 及更早格式明确拒绝。
- 深度上限是实现资源约束，不是 FDT 格式本身的限制。
- 尚未提供按绝对路径查找节点、按名字查找属性或解析单元格/字符串列表的便捷接口；调用方可以遍历事件并检查原始属性值。
- 尚未解释任何 Linux 或平台专用设备树 binding，因此目前不能据此发现物理内存范围或初始化硬件。
- 从 OpenSBI 地址形成完整 DTB 切片仍依赖固件交接契约保证该段内存可读。

内存范围的最小平台语义提取已在[第 5 阶段](phase-5-boot-memory-info.md)单独实现；本通用读取器仍不承担 binding 解释。
