# 第 18 阶段：用户任务定时器抢占

## 目标关联

第 17 阶段依赖 `sched_yield` 协作切换。`fullemu_user_cpu_hog` 不主动让出 CPU 时，其他就绪任务只能等它结束。本阶段把此前在内核任务实验中建立的 SBI 定时器和完整陷入帧机制接入 U-mode 调度路径，避免单个用户任务长期独占 CPU。这是运行任意用户程序时维持系统响应和任务进展的必要基础。

## 学习重点

- `sched_yield` 由任务主动触发；定时器中断由硬件和固件异步触发，即使任务不合作，内核也能重新获得控制权。
- 定时器中断可能落在用户指令执行的任意位置。陷入汇编保存全部整数寄存器和关键 CSR，调度器保存当前 `TrapFrame` 并恢复另一任务的帧。
- SBI TIME 扩展由 OpenSBI 设置下一次 supervisor timer interrupt。QEMU `virt` 的 `time` 计数频率为 10 MHz，本阶段每 100,000 tick 重新安排一次中断，即约 10 ms 时间片。
- 定时器只提供抢占时机；本阶段继续使用现有按任务清单顺序轮转的调度策略，不加入优先级或动态就绪队列。

## 实现范围

- 架构层 `arch::riscv64::interrupt` 只开启 supervisor timer interrupt；`arch::riscv64::sbi` 设置下一次定时器截止时间。S-mode 全局中断使能仍通过 `sret` 的状态位转换，不在普通内核路径中无条件打开。
- 首个用户任务启动前设置定时器并启用 `sie.STIE`。用户任务运行期间收到定时器中断后，内核重新安排下一个时间片。
- 若陷入来自 U-mode，调度器保存当前任务帧，将任务置为就绪，并按原轮转策略选择下一个任务。被切出的任务之后从中断处继续执行，不推进 `sepc`。
- 原有 `sched_yield` 和 `exit` 行为保持不变。协作切换与时间片到期都使用同一组任务状态、陷入帧和调度选择逻辑。
- 时间片常量暂按 QEMU `virt` 的 10 MHz timebase 设置；若 SBI 调用失败或截止时间计算溢出，内核记录错误并停机，避免悄悄退化为不可抢占状态。

## 暂不实现

- 时间片固定为 10 ms；不支持优先级、动态调节、负载均衡或多 hart 调度。
- 当前只保存整数寄存器和陷入所需 CSR，不保存浮点寄存器。用户程序不得在抢占点间依赖浮点寄存器中的值；引入浮点程序前必须补全并验证浮点上下文保存，或在用户构建中禁用相关指令。
- 用户任务仍运行在 `satp=BARE` 下，可以访问内核和其他任务的内存。定时器抢占改善 CPU 公平性，不提供内存隔离或安全边界。
- 定时器只抢占正在运行的任务；没有阻塞状态、等待队列、空闲任务或设备中断唤醒。
- 时间基准固定使用 QEMU `virt` 的已知频率，尚未从 FDT 读取 `timebase-frequency`，因此不能据此声称已支持其他 RISC-V 平台。

## 运行与验收

```sh
make fmt-check
make build
make run
```

QEMU 串口中，`cpu_hog` 输出开始消息后，其他就绪任务应能在其完成消息之前输出或结束；约 15 亿次循环完成后，`cpu_hog` 也应继续运行并正常退出。协作任务仍应交错输出，所有任务结束后内核应报告调度完成。该顺序证明 CPU 密集任务被时间片切出，而不是主动调用 `sched_yield`。

## 后续连接

定时器抢占解决了不合作任务造成的 CPU 饥饿，但所有 U-mode 任务仍能访问同一物理内存。下一步建立 Sv39 地址空间并限制用户访问范围，使进程获得独立地址空间；之后可在该任务模型上实现阻塞 I/O 和唤醒。
