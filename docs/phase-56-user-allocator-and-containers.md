# 第 56 阶段：用户态 Rust 分配器与容器

## 目标关联

第 53 阶段已经让每个进程通过 Linux RISC-V `brk` syscall 增长和缩小自己的用户堆，但用户程序仍只能手动管理字节缓冲区。用户态分配器把内核提供的页级堆空间转成 Rust 对象分配接口，使 `Vec`、`String` 和 `Box` 能在独立用户程序中使用。

## 学习重点

- 内核负责维护进程 break、映射清零页并拥有物理页帧；用户分配器只管理已映射堆中的字节区间。
- `GlobalAlloc` 把 Rust `alloc` crate 的对象布局请求交给运行库实现。
- 分配器以有序空闲链表切分空闲块，释放时按地址重新插入并合并相邻块。
- 空闲对象块可复用，但当前不把空闲页归还内核；只有用户堆缩短 break 才会回收物理页。

## 实现范围

- `fullemu_user::alloc` 公开 Rust 核心库提供的 `alloc` crate，不增加第三方依赖。
- `user::allocator` 实现进程私有的 `GlobalAlloc`。首次分配时查询当前 break；空间不足时按需通过 `brk` 扩展到页边界。
- 分配器记录每个分配块的边界信息，以支持任意 `Layout` 对齐；`dealloc` 负责校验头部、维护空闲链表并合并相邻块。
- 添加 `alloc_demo`，使用 `Vec`、`String` 和 `Box`，触发容器扩容与释放后复用；并在 fork 后让子进程继续扩展 `Vec`，验证进程复制时分配器状态和堆页彼此独立。
- 分配失败按 `GlobalAlloc` 约定返回空指针，由 Rust 分配接口触发本项目的 panic handler；本阶段不实现可恢复分配 API。

## 边界与限制

- 当前每个进程只有一个用户态执行流，因此分配器没有锁。添加线程或同一地址空间内的并发执行前，必须先为分配器状态增加同步。
- `fork` 通过复制进程私有数据页和堆页复制分配器状态；`exec` 使用新映像的零初始化数据段获得未初始化的新状态。
- 分配器保留已取得的页，不因容器释放而缩小 break；重复分配可复用空闲块，进程退出时内核统一回收全部堆页。
- 当前不提供 `mmap`、独立分配区、懒分配、线程安全、用户态 `std`、OOM 恢复或堆统计 API。
- 公开的原始 `syscall::brk` 不应与全局分配器同时用于管理同一个 break；分配器负责维护其取得的堆范围。

## 模块边界

`user::allocator` 依赖 `user::syscall::brk` 和 Rust `core::alloc::GlobalAlloc`；用户程序通过重新导出的 `alloc` crate 使用标准容器。内核不依赖或了解用户空闲链表；`syscall` 只将 `brk` 请求交给 `process::user_heap`，后者通过 `memory::address_space` 和 `frame_allocator` 管理映射与页帧。

## 验收方式

```sh
make fmt-check
make build
make run
```

在 shell 中运行 `alloc_demo`。程序应输出 `Vec` 的长度、容量和 `Box` 内容，随后报告容器释放后可复用堆空间，并以状态码 0 返回 shell。该程序还会 fork 子进程，在子进程中扩展 `Vec`，再检查父进程的长度和数据保持不变。继续运行 `heap_test`，确认内核堆页管理原有行为不受用户分配器影响。

## 后续连接

用户程序现在可以使用拥有型 Rust 容器。后续工作可以选择在真实消费者出现时补充用户态文件读取缓冲、动态参数列表等能力；若引入线程或并发执行，则先为全局分配器定义并验证同步策略。
