# 第 54 阶段：EasyFS 风格的简易文件系统

## 目标关联

当前系统已经能逐扇区读写 VirtIO 块设备，但用户程序还没有持久化文件接口。本阶段建立 EasyFS 风格的磁盘布局和最小 inode 文件操作，使内核代码可以创建目录和文件，并按偏移读写文件内容。QEMU 使用可复用镜像，卷跨正常退出和再次启动保留内容。

## 学习重点

- 块设备只提供扇区读写；文件系统负责定义磁盘内容的含义。
- 超级块标识文件系统格式并记录各磁盘区域的位置和长度。
- 磁盘格式是持久 ABI：字段偏移、宽度、字节序和版本必须明确编码，不能直接把 Rust 结构体内存写入磁盘。
- [rCore EasyFS](https://rcore-os.cn/rCore-Tutorial-Book-v3/chapter6/2fs-implementation.html) 采用超级块、inode 位图、inode 区、数据位图和数据区的顺序布局。本项目沿用这个便于教学的组织方式，并自行实现磁盘编码和区域计算。
- 格式化和挂载是不同操作。超级块和全部元数据区域为空时才自动格式化；未知的非空元数据必须拒绝覆盖。
- inode 保存文件长度、类型和直接数据块地址；目录数据区保存固定长度的目录项。
- 文件系统对象持有块设备，向上层提供 inode 与文件操作，不暴露扇区布局。
- QEMU 正常退出后的数据复用不等于异常断电一致性；当前块设备契约还没有 flush 请求。

## 实现范围

- `FileSystem<D>` 通过 `block::BlockDevice` 访问并持有设备，不依赖 VirtIO、FDT 或 Linux syscall，也不引入 rCore crate 或同步依赖。
- 超级块位于逻辑扇区 0，保存魔数、格式版本、扇区大小、设备容量、挂载次数和区域布局。
- inode 数量固定为 128，inode 大小为 128 字节。磁盘区域依次为超级块、inode 位图、inode 区、数据位图和数据区。
- 根目录 inode 编号为 0；格式化时占用位图第一位，并将根 inode 类型标记为目录。
- 每个 128 字节 inode 保存一个 64 位文件长度、对象类型和 14 个 64 位直接扇区号；单个文件最多 7168 字节，不支持间接块或稀疏文件。
- 目录项固定为 32 字节：4 字节 inode 编号和 28 字节名称区域。名称为 UTF-8 字节串，不能包含 NUL 或 `/`，最多 27 字节。
- `FileSystem` 提供 `format`、`mount`、路径解析、目录枚举、文件/目录创建、普通文件删除、元数据查询和按偏移读写。写入只允许覆盖已有内容或从文件末尾追加，不允许越过文件末尾形成空洞。
- 目录删除和重命名仍不支持；第 55 阶段添加了普通文件删除。文件仍不支持间接块和超过直接块上限的内容。
- 数据位图大小按设备容量计算。挂载时重新计算布局并验证超级块记录、根 inode 和 inode 位图。
- 首次启动仅在超级块及全部元数据扇区为零时格式化；之后验证卷格式并递增挂载次数。写入扇区后立即读回逐字节校验。
- QEMU 默认复用 `target/fullemu-filesystem.img`；可用 `BLOCK_IMAGE` 指定其他镜像。镜像不存在时创建 16 MiB 空白 raw 文件，已存在时保留内容。
- 移除会覆盖固定扇区的 VirtIO 启动读写自检，由文件系统元数据读写承担当前启动验证。

### 扇区 0 的超级块布局

所有整数均为小端编码；扇区剩余字节写零并保留给后续版本扩展。

| 字节范围 | 大小 | 含义 |
| --- | ---: | --- |
| `0..8` | 8 字节 | 卷魔数 `FULLEMU\0` |
| `8..12` | 4 字节 | 格式版本，当前为 2 |
| `12..16` | 4 字节 | 逻辑扇区大小，当前为 512 |
| `16..24` | 8 字节 | 格式化时的设备扇区数 |
| `24..32` | 8 字节 | 成功挂载次数 |
| `32..40` | 8 字节 | inode 位图占用扇区数 |
| `40..48` | 8 字节 | inode 区占用扇区数 |
| `48..56` | 8 字节 | 数据位图占用扇区数 |
| `56..64` | 8 字节 | 数据区占用扇区数 |
| `64..72` | 8 字节 | inode 数量，当前为 128 |
| `72..80` | 8 字节 | 根 inode 编号，当前为 0 |
| `80..88` | 8 字节 | 数据区起始扇区编号 |
| `88..512` | 424 字节 | 保留，当前写零 |

### 区域顺序

| 区域 | 起始扇区 | 长度 |
| --- | ---: | ---: |
| 超级块 | 0 | 1 扇区 |
| inode 位图 | 1 | 1 扇区 |
| inode 区 | 2 | 32 扇区，存放 128 个 inode |
| 数据位图 | 34 | 根据设备容量计算 |
| 数据区 | 由超级块记录 | 剩余扇区 |

inode 记录中，偏移 `0..8` 保存文件长度，偏移 `8` 保存类型，偏移 `16..128` 保存 14 个直接扇区号。空闲 inode 和数据块由各自的位图管理。根目录 inode 初始长度为 0，创建目录项时按需分配数据扇区。

## 暂不实现

- 间接块、稀疏文件、目录删除、重命名、链接、块缓存及崩溃一致性。
- VirtIO flush、崩溃一致性、日志或写时复制。
- 分区表、多个块设备、并发请求和设备中断。

## 模块边界

`filesystem` 定义卷格式、inode 和目录/文件操作，并通过 `BlockDevice` 完成扇区访问；`startup` 从 FDT 发现块设备并初始化文件系统；`driver::virtio::block` 负责 VirtIO 协议和具体 I/O。第 54 阶段之后，挂载对象由文件系统模块持有，syscall 经 `filesystem::with_mounted` 访问它。当前单 hart 的块 I/O 使用轮询，尚无块缓存或并发访问。

## 验收方式

```sh
make build
make run
```

首次运行应输出文件系统已格式化、inode 数量 128 和挂载次数 1。正常退出 QEMU 后再次执行 `make run`，应输出文件系统已挂载及挂载次数 2。也可用 `BLOCK_IMAGE=/绝对路径/disk.img make run` 指定另一个可复用镜像。

将未知非空镜像指定为 `BLOCK_IMAGE` 时，内核应报告卷格式无效并停止，不得自动格式化。第 54 阶段早期试验格式使用版本 1，当前 inode 布局已改为版本 2；旧版本卷会被拒绝，需要用新的空镜像继续实验。执行 `make clean` 会删除默认位于 `target/` 下的镜像；需要长期保留时应使用仓库外的 `BLOCK_IMAGE` 路径。
