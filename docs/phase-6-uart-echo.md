# 第 6 阶段：UART 单字节输入与回显

## 目标

在已有串口格式化输出基础上，增加最小的输入路径：内核轮询 QEMU `virt` 的 NS16550 UART，等待一个字节到达后读取并立即回显。该路径为后续行编辑和 shell 输入建立硬件基础。

## 实现范围

- `read_byte` 轮询线路状态寄存器的 Data Ready 位；没有输入时阻塞等待，有数据时读取接收缓冲寄存器。
- `write_byte` 通过现有发送寄存器输出一个字节，换行字节会按终端约定转换为 CRLF。
- 启动诊断输出完成后，内核进入单字节回显循环。输入的 UTF-8 字节会原样逐字节回显；换行字节按输出约定处理。
- 继续使用 QEMU `virt` 的固定 UART0 地址 `0x10000000`，所有 MMIO 访问仍集中在 RISC-V 平台 console 模块中。

## 运行与验证

```sh
make build
make run
```

等启动信息结束并看到“串口字节回显已就绪，请输入字符：”后，在运行 `make run` 的终端中输入文字。字符应立即显示在串口上；按回车可观察换行回显。按 `Ctrl-C` 结束 QEMU。

也可以通过管道向 QEMU 的标准输入发送字节进行自动检查，例如：

```sh
printf 'abc\n' | make run
```

管道会在输入结束后关闭；QEMU 仍会保持运行，需按 `Ctrl-C` 结束。

## 当前限制

- 输入采用忙等待轮询，会持续占用当前 hart；尚未启用 UART 接收中断或调度器。
- 每次只读取并回显字节；没有行缓冲、退格处理、输入编辑或命令解析。
- 尚未处理 UART 接收错误状态，也没有为多个并发调用提供串口锁。
- UART 地址仍固定为 QEMU `virt` 的 UART0，尚未通过 FDT 发现控制台设备。
