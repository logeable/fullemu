# 第 8 阶段：协作式上下文切换

## 问题

第 7 阶段展示了没有调度器时，持续运行的任务 A 会让任务 B 永远无法开始。本阶段加入最小的 CPU 虚拟化机制：任务在明确调用 `yield_now` 时保存自己的执行位置，让另一个任务继续运行。

## 实现范围

- 运行两个内核任务，各自拥有 16 KiB、16 字节对齐的静态栈；两个任务仍共享同一地址空间。
- 用固定大小的轮转调度器在任务 A 和任务 B 之间切换，不动态分配任务或栈。
- `TaskContext` 保存返回地址、栈指针和 RISC-V 整数被调用者保存寄存器；汇编切换代码依照 RISC-V 调用约定恢复另一个任务。
- 两个任务都在输出计数后显式调用 `yield_now`。启动时 S-mode 中断保持关闭，因此调度状态只会在明确的让出点改变。
- 当前上下文不保存浮点寄存器；实验任务不得在让出点之间持有浮点状态。后续若允许任务使用浮点运算，必须扩展上下文定义。
- 两个任务暂时共享 `gp`、`tp`；当前不使用线程局部存储。后续若引入每任务 TLS，必须把线程指针纳入任务切换状态。

## 运行与验收

```sh
make build
make run
```

启动信息后应交替看到“任务 A”和“任务 B”的运行计数持续增长。将 `task_a_entry` 中的 `yield_now()` 临时注释掉并重新运行，预期只看到任务 A 的计数，任务 B 不再取得运行机会；恢复该调用后，两者应再次交替推进。

## 本阶段暂不实现

- 定时器中断和抢占式调度。任务不主动调用 `yield_now` 时仍可独占 CPU。
- 用户态、独立地址空间和内存保护；任务 A 可以访问任务 B 的内存。
- 任务阻塞、退出、优先级、空闲任务、多 hart 并发及浮点上下文保存。

这些限制把本阶段聚焦于上下文切换本身。下一步可用定时器抢占回应“任务不配合时，内核如何收回 CPU”的问题。
