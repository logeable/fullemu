# 第 3 阶段：FDT 结构块遍历（阶段记录）

## 目标

在头部校验基础上，从结构块起点顺序读取 token，确认节点嵌套和区块边界有效，并列出根节点下的直接子节点名称。遍历器不解释硬件属性的含义，也不复制数据或申请堆内存。

本阶段记录保留最初的遍历目标；后续增加的完整布局校验、保留表和属性借用接口见[第 4 阶段](phase-4-fdt-reader.md)。

FDT 结构块由 32 位大端 token 及其附加数据组成，token 按 4 字节对齐。节点名以零字节结束；属性项包括值长度、字符串块中的名称偏移和属性值。参见 [Devicetree 规范：结构块](https://devicetree-specification.readthedocs.io/en/v0.2/flattened-format.html)。

## 实现范围

- `FdtStructureWalker` 在已验证的头部范围内切分结构块和字符串块，并逐项产生只读事件。
- 支持 `FDT_BEGIN_NODE`、`FDT_END_NODE`、`FDT_PROP`、`FDT_NOP` 和 `FDT_END` 五种 token。
- 校验节点名与属性名的结束符和 ASCII 格式、属性名偏移、属性值与对齐范围、节点嵌套、单根节点以及 `FDT_END` 位置。
- 按规范校验节点名称后的零填充。属性值后的填充只检查范围并跳过内容：QEMU 10.2.2 的 `virt` DTB 在属性对齐位置出现非零字节，因此本阶段为保证首要模拟器可启动，对属性填充值采取兼容处理。
- 遍历器只向调用方提供属性名和值长度，不暴露属性值。内核启动路径只输出根节点的直接子节点名称。
- 不读取 `/memory`、`/chosen` 等节点属性，不更改 UART 地址，也不实现内存分配。
- 不引入第三方依赖；可在宿主机运行纯 Rust 测试。

## 验证

```sh
make test-fdt
make run
```

宿主机测试覆盖有效嵌套树、非零属性对齐填充、非法节点名填充、截断 token、未结束节点名、属性名偏移越界、属性值越界以及缺少 `FDT_END`。QEMU 启动时应在头部摘要后输出根节点的直接子节点，例如 `cpus`、`memory@80000000` 和 `soc`。

## 本阶段结束时的限制

- 不解释属性值，不解析 `reg`、`#address-cells` 或 `#size-cells`。
- 遍历器验证节点嵌套和字节边界，但尚未验证所有 DTSpec 语义规则，例如父节点属性必须出现在子节点之前。
- 节点名和属性名当前限制为 ASCII。
- 从 OpenSBI 地址创建 DTB 切片仍依赖固件交接契约保证该段内存可读；后续内存映射设计需重新审视此安全边界。
