# 第 46 阶段：exec 替换当前进程映像

## 目标关联

第 45 阶段让进程可以创建子进程并等待其退出，但子进程只能继续运行父进程的同一份程序映像。用户态 `init` 或 shell 要启动另一个程序，需要把子进程替换为目标程序。本阶段建立这条最小路径，为后续由 `init` 启动 shell、由 shell 启动命令程序打基础。

## 学习重点

`exec` 不创建新进程，而是替换当前进程的用户程序映像。PID、父子关系和内核栈保持不变；用户程序入口、用户栈和用户地址空间发生变化。新资源必须先完整准备好，随后切换到新地址空间，再释放旧映像，避免加载失败时破坏原进程。

## Linux RISC-V ABI 边界

内核通过 `execve` syscall（编号 221）提供最小替换能力。当前只接受 `/bin/<程序名>` 路径，并从构建期嵌入的用户程序清单中查找镜像；`argv` 和 `envp` 必须为空。成功时从新程序入口恢复用户态，不返回旧调用点；失败时返回负的 Linux errno，旧映像继续运行。

用户库提供 `syscall::exec(path)`，为路径构造 NUL 结尾缓冲区并传入空参数数组。路径字符串必须在当前进程的程序映像或用户栈范围内，且长度不超过 127 字节。无效指针返回 `EFAULT`，路径过长返回 `ENAMETOOLONG`，未找到嵌入程序返回 `ENOENT`，不支持非空参数或环境数组返回 `EINVAL`，无效镜像布局返回 `ENOEXEC`，新资源不足返回 `ENOMEM`。

这不是完整 Linux `execve` 支持：没有文件系统路径解析、ELF 装载、参数和环境变量复制、脚本解释器或可执行文件权限检查。

## 实现范围

- syscall 层校验并复制用户路径，再把嵌入程序索引交给进程模块。
- `process::exec` 创建新镜像、新用户栈和新地址空间；新地址空间映射当前进程的内核栈。
- 新页表激活后，进程对象替换地址空间、程序镜像、用户栈和程序范围；PID、父子关系、内核栈及陷入帧所在地址保持不变。
- 新陷入帧从目标程序入口和新用户栈顶开始执行，并重置旧程序寄存器现场。
- 旧地址空间切离后销毁其页表，再释放旧镜像页和用户栈页。
- 用户程序入口支持 `main() -> i32`：正常返回的整数作为进程退出状态；`main() -> ()` 继续默认以 0 退出。`exec_target` 返回 23，入口将其交给 Linux `exit` syscall。
- `exec_test` 创建子进程，让子进程 exec 到 `exec_target`；父进程 wait 并验证目标程序返回的退出码。

## 暂不实现

- 不支持 `argv`、`envp`、文件系统、ELF 解析或动态链接。
- 不支持多个线程或 exec 期间的并发执行；当前系统按单 hart、单线程进程模型运行。
- 不增加 shell 命令或 init 启动策略。

## 验收方式

```sh
make fmt-check
make build BOOT_PROGRAM=exec_test LOG_LEVEL=info
make run BOOT_PROGRAM=exec_test LOG_LEVEL=info
```

运行时应看到子进程调用 exec、`exec_target` 的新映像开始运行并从 `main() -> i32` 返回 23；`user_entry!` 应将该状态传给 `exit`，父进程 wait 后打印 `exec 验证通过`。若路径不存在或参数不受支持，调用应返回 errno，原程序仍能继续执行。

## 后续连接

该接口让用户态 init 能派生子进程并 exec 成 shell，也让 shell 能 exec 为独立命令程序。下一阶段由 init 组合现有 `fork`、`exec` 和 `wait` 管理 shell 生命周期；之后可增加参数和环境数组复制，再将内嵌镜像查找替换为文件系统路径加载。
