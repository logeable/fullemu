# 第 35 阶段：按链接段设置内核页权限

## 目标关联

用户和内核已拥有不同的特权级与页表权限，但此前整个内核映像都映射为可读、可写、可执行。按段建立页权限能明确表达内核代码、常量和可变状态的用途，是 Sv39 地址空间实验的一部分，也为后续查找内核误写代码页或从数据页取指问题提供硬件边界。

## 实验问题

**内核映像中的代码、只读数据和可变数据应当具有相同的页权限吗？若不相同，链接器和页表如何共同保证权限边界？**

## 实现范围

- 链接脚本将 `.text`、`.rodata`、`.data`、`.bss` 的起始位置分别对齐到 4 KiB 页边界。
- 用户任务创建时从链接器符号收集具名段范围，并通过 `KernelMemoryLayout` 传给 `memory`；memory 校验范围顺序和页对齐不变量。
- 页表仍先把 FDT RAM 恒等映射为 S-mode 可读写，再覆盖内核各段权限：`.text` 为 `SR-X`，`.rodata` 为 `SR--`，`.data` 和 `.bss` 为 `SRW-`。
- 用户镜像、用户栈、UART、内核链接地址和 RAM 恒等映射策略保持不变。没有改变高半区地址规划，也没有重构物理页分配或用户镜像生命周期。

段与段之间的填充页仍落在前一段最后一页的权限范围内；链接器页对齐使不同权限的段不会共享一个 4 KiB 页。未被内核各段覆盖的 FDT RAM 页面仍是 S-mode 可读写映射。

## 模块边界

`task::creation` 读取链接器符号并组装 `KernelMemoryLayout`，因为它负责准备任务创建所需的映射输入。`memory` 校验段范围并实现页表权限策略；链接脚本只定义段的位置与边界。页表 PTE 位和 `satp` 操作仍封装在 `memory::page_table`。

## 验收

- 构建 ELF 后检查 `.text`、`.rodata`、`.data`、`.bss` 的开始地址均按 `0x1000` 对齐，且各段顺序符合 `KernelMemoryLayout` 校验。
- 启动 QEMU shell，确认任务能进入用户态并执行 `help`。
- 启动 QEMU batch，确认普通任务退出、协作调度、非法指令处理和用户非法地址页故障仍按现有行为工作。
- 使用页表诊断日志确认内核 `.text` 显示 `SR-X`、`.rodata` 显示 `SR--`，从 `.data` 开始的可写区域显示 `SRW-`；由于 `.data`、`.bss` 与普通 RAM 使用相同权限，日志可能将它们合并为一个连续范围。用户镜像与用户栈权限保持 `URWX`、`URW-`。

## 后续连接

高半区内核迁移仍是单独阶段。该迁移需要处理启动时临时映射、`sp`、`gp`、`stvec`、陷入帧以及页表和物理页访问方式，不应与本阶段的权限细分混在一起。
