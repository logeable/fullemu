# 第 27 阶段：用容器管理地址空间记录

## 目标关联

页表根页已经由物理页帧分配器动态分配，但其地址仍保存在固定长度数组中。本阶段让内核堆中经过验证的 `Vec` 管理这些根页地址记录，为后续把任务和地址空间改造成拥有明确生命周期的内核对象打基础。

## 实验问题

**页表根页由页帧分配器管理时，内核如何保存可变数量的地址空间记录，并在销毁后避免再次使用旧根页？**

## 实现范围

- 用 `Vec<Option<usize>>` 保存按稳定索引排列的地址空间根页物理地址；空槽表示对应地址空间尚未建立或已经销毁。
- 初始化时通过 `try_reserve_exact` 一次性申请记录容量，并将堆分配失败转换为明确的页表错误。
- 激活、销毁和调试输出都通过地址空间容器读取根地址。销毁后将槽位设为 `None`，保留索引位置，避免影响调度器已有的任务索引。
- 根页表和中间页表的实际物理页仍由固定物理页帧池分配、销毁；`Vec` 只管理内核中的地址空间记录。
- 任务上限仍为 8；用户栈、内核陷入栈、任务状态和程序镜像仍使用现有静态布局。本阶段不实现动态任务创建。

## 暂不实现

- 不将页帧分配器接入堆，也不扩展固定的物理页池。
- 不动态分配任务栈、用户程序镜像或任务控制块。
- 不复用已销毁任务的索引，不改变现有调度策略。

## 运行与验收

```sh
make fmt-check
make build
make run BOOT_MODE=batch LOG_LEVEL=debug
```

QEMU 应继续启动批处理中的用户任务并输出各地址空间页表映射；任务退出后，其页表树应能按原有流程回收，之后对已清空槽位的激活请求应返回“地址空间尚未初始化”。

## 后续连接

后续可以将任务状态、陷入帧、栈和地址空间收拢到具有明确所有权的 `Task` 对象中，再逐步支持动态任务创建。届时还需要解决用户栈和程序镜像的动态分配与生命周期。
