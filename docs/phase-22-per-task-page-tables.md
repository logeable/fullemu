# 第 22 阶段：每任务独立 Sv39 页表

## 目标关联

第 21 阶段的 batch 模式让多个任务共用一张页表。虽然内核页面对 U-mode 不可访问，但每个任务也能读写其他任务的程序镜像和用户栈。本阶段为每个任务建立独立根页表，让 U-mode 只能访问当前任务自己的镜像和栈，形成后续动态任务管理所需的内存隔离基础。

## 实验问题

**多个任务同时驻留时，如何让它们使用同一物理内存而不能互相访问？** 本阶段仍使用恒等映射和固定物理槽位；不同之处是每个任务有自己的页表，只在该任务的页表中将自己的镜像与栈标记为 U-mode 可访问。

## 实现范围

- `kernel::memory` 为每个任务建立单独根页表。每张表都映射内核映像、BSS、所有内核陷入栈和 UART，但这些页面保持 `U=0`；只把该任务自己的程序镜像和用户栈映射为 `U=1`。
- 页表页仍从静态数组中分配，每个地址空间最多使用 8 张页表，最多支持 8 个任务；本阶段没有物理页分配器或堆。
- 任务切换时，调度器根据任务索引激活相应的 `satp` 根页表，并执行 `sfence.vma`。陷入处理器和下一任务的陷入帧都位于每张页表可见的 S-mode 内核映射中。
- 用户系统调用继续验证当前任务的镜像或用户栈范围；通过验证后，内核短暂设置 `sstatus.SUM` 访问当前地址空间中的用户缓冲区。
- `fullemu_user_memory_fault` 在 batch 模式尝试读取计算任务的程序页面 `0x80400000`。该地址在探测任务的页表中没有映射，预期触发 `LoadPageFault`，且其他就绪任务继续运行。

## 暂不实现

- 用户程序仍链接到各自固定虚拟地址，并通过恒等映射运行；尚未统一用户程序的虚拟入口或地址布局。
- 页表只区分 U-mode 与 S-mode 权限，内核映像自身没有按代码、只读数据和可写数据拆分权限。
- 任务及页表数量固定；不支持运行时创建地址空间、物理页分配、地址空间销毁、缺页处理、`fork` 或 `execve`。
- shell 和 batch 入口仍由构建配置选择，shell 不能动态创建任务。

## 运行与验收

```sh
make fmt-check
make build BOOT_MODE=batch
make run BOOT_MODE=batch
```

串口应报告多个用户任务已装入。内存隔离示例尝试读取 `0x80400000` 后应触发 `LoadPageFault`，`stval` 为 `0x80400000`；随后其他就绪任务仍应执行并结束。默认 `make run` 应仍启动 shell。

## 后续连接

每个已知任务已有独立地址空间，但地址空间和任务仍在启动时静态创建。后续可让 shell 通过受限接口请求内核创建任务；在扩展到运行时创建、回收和重复运行前，还需设计物理页及页表页的分配策略。
