# 第 23 阶段：统一用户程序虚拟入口

## 目标关联

每任务独立页表已经能够隔离用户程序和栈，但不同程序仍链接到不同虚拟地址。统一程序入口可让后续任务初始化和装载路径使用一致的用户代码布局，同时保留各程序互不重叠的物理镜像。该实验不依赖内核堆，也不改变任务、栈或页表的静态分配方式。

## 实验问题

**多个程序能否从同一个虚拟地址运行，同时让每个任务执行自己的物理镜像？** 每个任务的页表把 `0x80400000` 映射到该任务对应的物理镜像槽位。切换任务时切换页表，因此同一虚拟地址在不同任务中指向不同物理内容。

## 实现范围

- 用户构建脚本让所有 bin 链接到虚拟基址 `0x80400000`；链接脚本断言 `_start` 等于该基址，因此清单只需记录共同基址，不再存储恒为零的入口偏移。
- 内核仍按清单顺序将原始镜像复制到不同的 64 KiB 物理槽位。加载器分别保留程序虚拟基址和物理槽位地址，并直接以虚拟基址作为入口。
- 页表映射接口显式接收虚拟地址和物理地址。每个任务的程序虚拟区域映射到自己的物理槽位；内核、用户栈和 UART 继续按现有方式恒等映射。
- `write` 的程序镜像缓冲区检查改为验证共同虚拟区间，用户栈缓冲区检查保持不变。
- `memory_fault` 尝试读取 `0x80410000`，即共同 64 KiB 程序映射之外的地址；当前任务页表应拒绝该访问。

## 暂不实现

- 用户程序映像、页表、任务现场和用户栈仍使用静态容量；没有内核堆或物理页分配器。
- 用户栈地址尚未统一；没有 ELF 段装载、重定位、动态加载或文件系统。
- 本阶段只将程序映像区域作为整体映射，尚未区分代码、只读数据和可写数据权限。

## 运行与验收

```sh
make fmt-check
make build
make run
make build BOOT_MODE=batch
make run BOOT_MODE=batch
```

shell 模式应从 `0x80400000` 进入并显示提示符。batch 模式日志中的每个任务入口都应为 `0x80400000`，计算、I/O 和协作程序应正常运行；`memory_fault` 访问 `0x80410000` 时应触发 `LoadPageFault`，且其他任务继续执行。

构建时指定 `LOG_LEVEL=debug` 可查看每个任务的页表根地址及合并后的映射区间。每条映射包含虚拟范围、物理范围和权限标记：`S/U` 表示特权级，`R/W/X` 分别表示读、写和执行权限。例如，用户程序映射在各任务中有相同的虚拟范围，但物理范围不同。

## 后续连接

统一入口把程序虚拟地址与其物理存放位置分开，为将来的通用程序装载路径提供了更稳定的地址约定。当前任务与内存仍由静态数组管理；后续可先建立可回收的内核堆，再逐项替换有明确动态生命周期的内核对象，并单独设计用户页和页表页的物理分配。
